# Self-Implement — Code Generation

Take a work item from the backlog and implement it. Analyzes existing code patterns first, then generates code that matches the project's style.

## When to Use

- After `self-discover` generates a backlog
- When implementing a specific feature or fix
- As the code generation phase of the self-loop

## Input

A work item from `memory/backlog.md`, containing:
- Category (missing-test, error-handling, feature, refactor, etc.)
- Target file(s)
- Description of what's needed
- Estimated effort

## Phase 1: Pattern Analysis

Before writing ANY code, analyze the existing codebase:

### 1.1 Code Style Detection

```bash
# Detect Python style patterns
# Naming conventions (snake_case vs camelCase)
grep -rn "def " --include="*.py" app/ | head -20

# Import style (absolute vs relative)
head -20 app/main.py

# Type hints usage
grep -rn "def.*->.*:" --include="*.py" app/ | head -10

# Error handling patterns
grep -rn "try:" --include="*.py" app/ -A3 | head -20
```

### 1.2 Architecture Patterns

```bash
# How are services structured?
ls -la app/services/

# Database access patterns
grep -rn "def.*db\|cursor\|execute" --include="*.py" app/ | head -20

# API response format
grep -rn "return {" --include="*.py" app/main.py | head -10

# Schema patterns
head -50 app/schemas.py
```

### 1.3 Test Patterns

```bash
# Existing test style
find tests/ -name "*.py" -exec head -30 {} \; 2>/dev/null

# Test framework used
grep -rn "import pytest\|import unittest\|from fastapi.testclient" --include="*.py" tests/ 2>/dev/null
```

## Phase 2: Implementation

Based on the work item category:

### Category: Missing Test

1. Read the target file completely
2. Identify all public functions/methods
3. For each function:
   - Analyze inputs and outputs
   - Identify edge cases
   - Generate test cases (happy path, error cases, boundary)
4. Create test file following existing test patterns
5. Run tests to verify they pass

**Template:**
```python
"""Tests for {module_name}."""
import pytest
from app.{module_path} import {function_name}


class Test{FunctionName}:
    """Tests for {function_name}."""

    def test_happy_path(self):
        """Standard usage produces expected output."""
        # Arrange
        ...
        # Act
        result = {function_name}(...)
        # Assert
        assert result == expected

    def test_empty_input(self):
        """Empty input handled gracefully."""
        ...

    def test_invalid_input(self):
        """Invalid input raises appropriate error."""
        ...
```

### Category: Error Handling

1. Read the target function
2. Identify all external calls (DB, file, network, parsing)
3. Add try/except blocks following project patterns
4. Return appropriate error responses
5. Add logging if project uses logging
6. Test both success and error paths

### Category: Incomplete Feature

1. Read the TODO/placeholder
2. Understand the intended behavior from context
3. Implement the feature following project patterns
4. Add input validation
5. Add error handling
6. Create/update tests
7. Update any related documentation

### Category: Refactor

1. Read the target code
2. Identify the smell (duplication, complexity, etc.)
3. Apply refactoring pattern:
   - Extract method for long functions
   - Deduplicate repeated code
   - Simplify complex conditionals
   - Add type hints if missing
4. Run tests to verify no regressions

### Category: Missing Validation

1. Read the schema/model
2. Identify all fields that need validation
3. Add Pydantic validators / Field constraints
4. Add custom validators for business rules
5. Test with valid and invalid data

## Phase 3: Documentation

After implementation:

1. Add/update docstrings
2. Update README if public API changed
3. Add inline comments for complex logic
4. Record change in `memory/changelog.md`:

```markdown
## YYYY-MM-DD — {work_item_title}
- **Category:** {category}
- **Files changed:** {file_list}
- **What:** {one-line description}
- **Tests added:** {yes/no, count}
```

## Quality Checklist

Before marking a work item as done:

- [ ] Code follows project naming conventions
- [ ] Error handling is present for all external calls
- [ ] Input validation is complete
- [ ] Tests cover happy path and error cases
- [ ] No hardcoded values (use config/constants)
- [ ] No unused imports
- [ ] Docstrings added/updated
- [ ] Changelog updated

## Integration

- Reads backlog from `memory/backlog.md` (generated by `self-discover`)
- `self-test` validates the implementation
- `self-fix` handles any test failures
- `self-loop` orchestrates the full cycle
- Changes are auto-committed when tests pass (managed by `self-loop`)
