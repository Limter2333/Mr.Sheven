# Self-Fix — Auto-Fix Loop

Take test failures and bugs, analyze root causes, apply fixes, and re-test. Iterates until all tests pass or max attempts reached.

## When to Use

- After `self-test` reports failures
- When tests are failing and need fixing
- As the fix phase of the self-loop

## Input

Read the test report from `memory/test-report.md` (generated by `self-test`).

## Fix Loop

For each failure, run up to **3 fix attempts**:

```
for each failure:
    attempt = 0
    while attempt < 3:
        1. ANALYZE — Read error, understand root cause
        2. FIX — Apply targeted fix
        3. RE-TEST — Run the failing test
        4. if passes: break
        5. attempt++
    if still failing: ESCALATE to user
```

## Phase 1: Root Cause Analysis

For each failure, determine the category and read relevant code:

### Parse Error Message

```bash
# Extract the specific error from test output
# Common patterns:
# AssertionError: assert X == Y
# TypeError: missing argument
# ValueError: invalid input
# AttributeError: NoneType has no attribute X
# ImportError: cannot import name X
# KeyError: 'missing_key'
```

### Read Context

1. Read the failing test file (full test function)
2. Read the source file being tested
3. Read any recently changed files (git diff)
4. Check imports and dependencies

### Classify Root Cause

| Error Type | Root Cause | Fix Strategy |
|------------|-----------|--------------|
| AssertionError | Logic error or wrong expected value | Fix logic or update assertion |
| TypeError | Missing/wrong arguments | Fix function signature or call |
| ValueError | Validation too strict/loose | Adjust validation logic |
| AttributeError | None returned where object expected | Add null check |
| ImportError | Missing import or renamed symbol | Fix import statement |
| KeyError | Missing dict key | Add key access with .get() |
| FileNotFoundError | Wrong path | Fix path construction |
| ConnectionError | Service unavailable | Mock dependency in test |

## Phase 2: Apply Fix

Based on root cause:

### Fix: Logic Error

```python
# Read the source function
# Identify the incorrect logic
# Apply correction
# Example: wrong operator
# Before: if count > 10
# After:  if count >= 10
```

### Fix: Missing Error Handling

```python
# Add try/except around the failing code
try:
    result = risky_operation()
except SpecificException as e:
    result = default_value
    log.warning(f"Handled: {e}")
```

### Fix: Missing Validation

```python
# Add input validation
if not input_value:
    raise ValueError("input_value is required")

# Or with Pydantic
class Request(BaseModel):
    field: str = Field(..., min_length=1)
```

### Fix: Wrong Import

```python
# Fix the import path
# Before: from app.services.wrong import function
# After:  from app.services.correct import function
```

### Fix: Test Assertion Mismatch

```python
# If the source code changed behavior legitimately:
# Update the test to match new behavior
# Document WHY the assertion changed
def test_feature():
    """Updated: feature now returns empty list instead of None."""
    result = my_function()
    assert result == []  # was: assert result is None
```

### Fix: Missing Mock

```python
# Add mock for external dependency
@patch("app.services.module.external_api")
def test_with_mock(self, mock_api):
    mock_api.return_value = {"status": "ok"}
    result = my_function()
    assert result["success"] is True
```

## Phase 3: Re-Test After Each Fix

```bash
# Run only the failing test (fast feedback)
python -m pytest tests/test_file.py::TestClass::test_method -v --tb=short 2>&1

# If passes, run the full test file to check for regressions
python -m pytest tests/test_file.py -v --tb=short 2>&1

# If file passes, optionally run full suite
python -m pytest tests/ -v --tb=short 2>&1
```

## Escalation

After 3 failed attempts, escalate to the user:

```markdown
## ⚠️ ESCALATION — Cannot Auto-Fix

### Failure: test_employee_update
- **File:** tests/test_employee.py:45
- **Error:** AssertionError: expected 200, got 500
- **Attempts:** 3
- **What I tried:**
  1. Added null check → still fails
  2. Fixed database query → still fails
  3. Updated test fixtures → still fails
- **Likely cause:** Deep business logic issue in update_employee
- **Recommendation:** Manual investigation needed

### Files to check:
- app/database.py (update_employee function)
- app/main.py (update_employee_api endpoint)
```

## Learning from Fixes

Track fix patterns to improve future fixes:

```markdown
## Common Fix Patterns (from fix-log.md)

1. **Missing validation** → Add guard clause at function entry
2. **NoneType access** → Add null check or use .get()
3. **Import error** → Check __init__.py exports
4. **Assertion mismatch** → Verify if behavior changed intentionally
5. **Mock missing** → Add @patch for external dependencies
```

## Integration

- Reads test report from `memory/test-report.md` (generated by `self-test`)
- Writes fix log to `memory/fix-log.md`
- `self-test` re-runs after each fix
- `self-loop` tracks fix success rate
